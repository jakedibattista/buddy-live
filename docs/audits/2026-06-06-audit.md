## File-by-File Notes

### `app/tools/*` (cross-cutting)
- **Redundancy (high):** `_now_iso()` is copy-pasted in **8** tool files (`set_focus_drill`, `set_iq_question_goal`, `mark_iq_answer`, `rep_capture`, `peek_warmup`, `peek_camera`, `show_iq_visual`, `warmup_timer`). `_get_session_id(tool_context)` is duplicated in **9** files (those + `callbacks.py`). `_yes(field)` is duplicated in `peek_camera` and `peek_warmup`. There is no shared tool-utility module.
- **Redundancy (med):** `_SESSION_SUMMARIES_COLLECTION = "session_summaries"` is declared independently in both `coaching.py` and `player_memory.py`.
- **Redundancy (med):** `_parse_peek_response` (`peek_camera`) and `_parse_warmup_response` (`peek_warmup`) share the same "split each line on `:` into an upper-cased field dict" preamble loop.

### `app/models.py`
- **Legacy/dead (med):** `PeekResponse` (L47) and `RepCaptureCommand` (L52) are defined but **never referenced** anywhere in the service. Tools return plain dicts; the SSE contract uses `ChatCompletionRequest`/`ChatMessage`. These two models are dead.

### `app/tools/rep_capture.py`
- **Dead code (med):** `_record_session_event` (L497) is defined but **never called** (only self-reference). It writes to a `coach_log` subcollection that nothing else reads. Remove or wire it in.
- **Poorly written / ADK risk (high):** `analyze_rep` advertises *"returns immediately"* / *"BACKGROUND"* / module docstring says *"uses NON_BLOCKING behaviour"*, but when the clip hasn't uploaded it runs a **synchronous busy-wait** (`time.sleep(1.0)` loop up to `ANALYZE_CLIP_WAIT_SECS=25`s, L280–294). On a slow upload this blocks the live voice turn for up to 25s. The "non-blocking" claim is aspirational, not implemented. See ADK 2.0 section.
- **Clarity (low):** `_SHOOTING_METRIC_LABELS` (L404) and `coaching.py`'s `_DRILL_RECOMMENDATIONS` keys both encode the shooting-metric vocabulary — two sources of truth for the same metric names.

### `app/tools/peek_camera.py` & `peek_warmup.py`
- **Efficiency (med):** Both build a fresh `genai.Client(api_key=...)` on **every** tool call (L217 / L274). `firestore_client` and `grounding` use cached singletons; the genai client should too (saves per-call construction; clients are reusable).
- **Clarity (low):** `peek_warmup` docstring says it analyzes "up to 3 frames," but `_TARGET_FRAME_COUNT = 4`. Off-by-one in the docstring.
- **Note:** structured-prompt parsing here is solid and well-commented; the strict MOTION→MOVING coupling is a nice guard. Keep.

### `app/agent.py`
- **Efficiency (low):** `_build_model()` is invoked **4×** (once per agent) producing 4 identical `Gemini` instances. They share identical config; one shared instance would do. Minor memory/init cost only.
- **ADK note (med, known/deferred):** `get_session_service()` returns `InMemorySessionService` — session state is lost on Cloud Run cold start and not shared across instances. Already documented as deferred in `ARCHITECTURE.md`; restating for completeness.
- **Clarity:** good module docstring + per-agent docstrings; the sub-agent split is clearly explained. Healthy.

### `app/callbacks.py` / `app/main.py` / `app/sse.py` / `app/telemetry.py` / `app/firestore_client.py` / `app/grounding.py`
- **Healthy.** Clear docstrings, graceful degradation, singleton patterns, and good comments explaining *why* (not *what*). `grounding.py` docstring says *"we already ship 12 function tools"* — **stale**, the agents now register **16** (see doc-consistency item).

### `apps/buddy-live/src/**` (frontend, light findings)

## Recommendations & Suggestions

Pick which to implement; nothing has been changed yet.

### 1. Redundancy & Legacy Code Removal
- **`app/tools/_common.py` (new):** extract `now_iso()`, `get_session_id(tool_context)`, `yes(field)`, a `parse_kv_lines(raw)` helper, and the shared `SESSION_SUMMARIES_COLLECTION` constant; update the ~9 tool files + `callbacks.py` to import them. _(severity: med, effort: medium)_
- **`app/models.py`:** delete unused `PeekResponse` and `RepCaptureCommand`. _(severity: med, effort: small)_
- **`app/tools/rep_capture.py`:** delete dead `_record_session_event` (or wire it into a real call site if coach-log telemetry is wanted). _(severity: med, effort: small)_

### 2. ADK 2.0 Optimization
- **Make `analyze_rep` genuinely non-blocking (highest leverage).** Either (a) drop the `time.sleep` wait loop and let the client/`get_rep_result` drive analysis once `storage_path` lands, or (b) register it as an ADK 2.0 `LongRunningFunctionTool` so the runner doesn't hold the turn. Today it can block a voice turn up to 25s while claiming the opposite. _(severity: high, effort: medium)_
- **Async tool I/O at concurrency=20.** All tools use sync `httpx.Client` + sync Firestore inside the async `Runner`; ADK runs them in a threadpool, so at `--concurrency=20` on one instance, slow vision/analysis calls tie up threads. Converting the network-bound tools (`peek_*`, `analyze_rep`, `get_rep_result`, grounding) to `httpx.AsyncClient` + async defs would scale better. _(severity: med, effort: large)_
- **Cache the `genai.Client`** in `peek_camera`/`peek_warmup` as a module singleton (mirror `firestore_client`/`grounding`). _(severity: med, effort: small)_
- **Share one `Gemini` model instance** across the 4 agents instead of calling `_build_model()` per agent. _(severity: low, effort: small)_
- **Durable sessions (deferred):** if cross-instance/cold-start memory ever matters for the demo, swap `InMemorySessionService` for a persistent `SessionService`. Currently safe because session state is reconstructed from Firestore on each turn. _(severity: low, effort: large — leave deferred)_

### 3. Clarity & Onboarding
- **Fix the tool-count drift:** `grounding.py` docstring ("12 function tools"), `README`, and the submission 1-pager should all say **16**. _(severity: low, effort: small)_
- **Reconcile the `Makefile` with the Vercel-only rule:** either remove/relabel the local `make dev`/ngrok targets, or add a one-line note that they're legacy and the supported path is Vercel + Cloud Run. _(severity: med, effort: small)_
- **Fix `peek_warmup` docstring** "up to 3 frames" → 4 (matches `_TARGET_FRAME_COUNT`). _(severity: low, effort: small)_
- **Single metric vocabulary:** consider one shared metric-label map consumed by both `rep_capture._SHOOTING_METRIC_LABELS` and `coaching._DRILL_RECOMMENDATIONS` to avoid drift. _(severity: low, effort: medium)_
