# Buddy Live evals

ADK eval harness backing the Track 2 (Optimize) submission. Runs the
production Buddy Live agent against synthetic players (User Simulation) with
all tools intercepted by Environment Simulation so nothing touches Firebase,
modelforpuckbuddy, or ElevenLabs.

See [`docs/TRACK2-PLAN.md`](../../../docs/TRACK2-PLAN.md) for the full Track 2
gap analysis and roadmap. Plain-language phase guide (including **Hockey IQ-only
eval** commands): [`docs/TRACK2-LAYMAN.md`](../../../docs/TRACK2-LAYMAN.md).
**Phase journal** (baselines, learnings, sequencing):
[`docs/TRACK2-PHASE-JOURNAL.md`](../../../docs/TRACK2-PHASE-JOURNAL.md).
This README only covers running the evals.

## Layout

| File | Purpose |
| --- | --- |
| `agent_module/` | Rebuilds the prod agent (+ `drill_coach`, `iq_coach`) wired to Environment Simulation instead of `phase_guard`. `adk eval` imports `root_agent` from here. **Keep in lockstep with `app/agent.py`.** |
| `environment_simulation.py` | Mock/injection configs for all production tools. Exports `happy_path_config()` and `failure_config()`. |
| `conversation_scenarios.json` | User-simulation scenarios with personas + conversation plans. |
| `optimize_sampler_config.json` | Phase 6: train/validation eval case split for `adk optimize`. |
| `optimize_config.json` | Phase 6: GEPA budget and output directory. |
| `OPTIMIZE.md` | Phase 6: how to run the Agent Optimizer loop. |
| `session_input.json` | Initial ADK session state (`session_id`, `user_id`). |
| `eval_config.json` | `hallucinations_v1` + `safety_v1` criteria and user simulator config. |
| `baselines/` | Saved `make eval-failures` logs for before/after comparisons (see [`docs/TRACK2-PHASE-JOURNAL.md`](../../../docs/TRACK2-PHASE-JOURNAL.md)). |
| `agent_module/coaching_scenarios.evalset.json` | Generated by `adk eval_set` on first run; do not edit by hand. |

## Prereqs

1. Python deps installed: `make install` from `services/buddy-live-adk/`.
2. `GOOGLE_API_KEY` (or Vertex credentials) in `services/buddy-live-adk/.env` where the agent and the user simulator both make Gemini calls.
3. ADK 2.x (`google-adk==2.0.0` already pinned in `requirements.txt`).

## Running

From `services/buddy-live-adk/`:

```bash
# Happy-path scenarios, where every mocked tool succeeds.
make eval

# Failure-injection variant, which adds probabilistic get_rep_result "processing"
# responses to stress edge-case handling.
make eval-failures

# Just one scenario by name (suffix the evalset path with `:eval_id`):
.venv/bin/adk eval \
  evals/agent_module \
  --config_file_path evals/eval_config.json \
  evals/agent_module/coaching_scenarios.evalset.json:<eval_case_id> \
  --print_detailed_results
```

The first `make eval` invocation creates
`evals/agent_module/coaching_scenarios.evalset.json` by wrapping each
scenario in `conversation_scenarios.json` into an EvalSet entry. After that
the evalset is cached on disk; delete it to regenerate after editing
scenarios.

## What each scenario tests

| Scenario id (first eval case) | What it exercises |
| --- | --- |
| Scenario 1 — `NOVICE`, wristshot full session | Baseline happy path: drill pick, warmup, reps, and recap |
| Scenario 2 — `NOVICE`, no space (`285f6d24` in eval set) | Sub-agent transfer from root coach to `iq_coach` for a **Hockey IQ eval** |
| Scenario 3 — `EXPERT`, slapshot, pushes back on warmup | Robustness to user corrections, sharper follow-up questions |
| Scenario 4 — `NOVICE`, eager but disorganized | Recovery from a player who can't follow setup instructions |
| Scenario 5 — `NOVICE`, impatient for results | Graceful waiting behaviour while `get_rep_result` is still processing |

Scenarios 4 & 5 are the most useful "before / after" demo material:

- Run `make eval-failures` to inject real tool failures matching the
  scenario's narrative (camera framing fails, results stay in `processing`).
- Capture the baseline scores; then iterate on `app/prompts.py` to handle
  these edge cases more gracefully and re-run to show the delta.

## Cost

Each scenario runs:

- One agent run using `gemini-flash-latest` for a full multi-turn conversation.
- One user simulator using `gemini-flash-latest` that drives the conversation.
- Two LLM-judged criteria (`hallucinations_v1` and `safety_v1`).

Budget roughly **$0.05–$0.20 per scenario** depending on conversation length
and how many tool calls the agent makes. Full evalset = ~$0.50–$1.00 per run.

## Why criteria are limited to `hallucinations_v1` and `safety_v1`

ADK's User Simulation is incompatible with criteria that need ground-truth reference responses or expected tool trajectories. The user simulator generates queries dynamically, so there is no fixed expected output. Per the [ADK eval criteria reference](https://github.com/google/adk-docs/blob/main/docs/evaluate/index.md), only `hallucinations_v1` and `safety_v1` support this mode today. Both are appropriate for Buddy Live: a children-facing voice coach must stay grounded in tool outputs (no made-up scorecards) and stay safe.

## Why a separate `agent_module/`

`adk eval` expects a module-level `root_agent`. Production `app/` uses a
`get_agent()` factory wired to a FastAPI bridge for the ElevenLabs Custom
LLM contract; the agent also has a Firestore-backed `phase_guard`
`before_tool_callback` on root + all sub-agents. Pointing `adk eval` at
`app/` would require monkey-patching both. The eval module instead imports
the prompt and tool symbols from `app.` and rebuilds the agent with
Environment Simulation as its `before_tool_callback`. Production wiring is
untouched.

`phase_guard` behaviour is tested hermetically in
[`tests/test_phase_guard.py`](../tests/test_phase_guard.py) (not via `adk eval`).
