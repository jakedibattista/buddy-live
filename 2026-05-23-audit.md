# Codebase Audit - 2026-05-23

## Goal
Optimize for clarity, remove redundancy and legacy code, and make onboarding easy for new developers.

## Scope
- **In scope:** Full Stack
  - Frontend (`apps/buddy-live/` - Next.js 16 Web App, components, custom hooks, and shared APIs)
  - Backend (`services/buddy-live-adk/` - FastAPI + Google ADK 2.0 Python agent, tools, and schemas)
  - Infrastructure (`infra/` - Cloud Build, Firebase/Firestore configurations and security rules)
  - Documentation (`docs/` - Architecture and Firestore deployment rules)
  - Root configuration files (`.gitignore`, `.env.example`, `README.md`)
- **Out of scope:** 
  - Dependency/build folders (`node_modules/`, `.next/`, `.venv/`, `tsconfig.tsbuildinfo`, `package-lock.json`)
  - Secrets and credentials (`.env`, `.env.local`, service account JSON keys)
  - Interactive testing or active model training scripts
- **Pacing:** Direct generation (completed in one comprehensive review of all files)

## File-by-File Notes

### `apps/buddy-live/src/hooks/useLiveSession.ts`
- **Clarity:** Extremely well-written state machine hook. Subscriptions are neatly cleaned up on unmount.
- **Redundancy/Legacy:** Minimal. Maps the database fields `rep_id` vs fallback `d.id` defensively.
- **Onboarding:** Easy to read, comments explain exactly how it ties anonymous Firebase auth, session endpoints, and Firestore subscriptions together.

### `apps/buddy-live/src/hooks/usePeekFrameUploader.ts`
- **Clarity:** Uses stable Canvas grabbing in React. High-quality inline code explanation.
- **Redundancy/Legacy:** Good performance optimizations by limiting canvas dimensions to 640px to keep base64 uploads lightweight.
- **Onboarding:** Clear documentation about why this polling mechanism was chosen over a live WebSockets stream (avoiding Gemini Live API limits).

### `apps/buddy-live/src/hooks/useRepCapture.ts`
- **Clarity:** Complex hook managing native browser media streams and timers.
- **Redundancy/Legacy:** Handled commands are recorded in a local React state `handledIdsRef = useRef<Set<string>>(new Set())` to prevent duplicate recording triggers.
- **Onboarding:** Detailed documentation on the "start_capture command to Firestore -> record -> API upload" loop.

### `apps/buddy-live/src/lib/types.ts`
- **Clarity:** Strong type safety detailing database document payloads, session phases, and response matrices.
- **Redundancy/Legacy:** Some duplication of model fields (e.g. `storage_path?: string; storagePath?: string;` and `job_id?: string; jobId?: string;`). This highlights a slight structural shift between camelCase (JS default) and snake_case (Python default) in the database.
- **Onboarding:** Invaluable file for developers wanting to map out the structure of Firestore records.

### `apps/buddy-live/src/app/api/session/route.ts`
- **Clarity:** High. Focuses strictly on creating or backfilling the session document.
- **Redundancy/Legacy:** Checks `adminConfigured()` and falls back gracefully to synthetic stubs if Firebase Admin keys are missing in local `.env` files.
- **Onboarding:** Clearly defines the validation and normalization bounds of focus drills.

### `apps/buddy-live/src/app/api/peek/route.ts`
- **Clarity:** Decodes base64 buffer and saves it to Google Cloud Storage under `peek_latest.jpg`.
- **Redundancy/Legacy:** Generates long-lived signed read URLs (4 hours) so the external ADK service can fetch the image without needing Google Storage credentials.
- **Onboarding:** Obvious data-flow direction. Easy to modify.

### `apps/buddy-live/src/app/api/clips/upload/route.ts`
- **Clarity:** Accepts recorded webm blobs via Multi-part FormData and uploads them.
- **Redundancy/Legacy:** Converts formats to correct file extensions (webm vs mp4) dynamically. Generates signed URLs for background analysis.
- **Onboarding:** Well documented. Shows how Next.js APIs bridge browser recordings to Google Cloud.

### `apps/buddy-live/src/lib/firebaseAdmin.ts`
- **Clarity:** Safe singleton loader. Prevents multiple Firebase Admin App initializations.
- **Redundancy/Legacy:** Replaces string escaped newlines `\\n` with standard backslashes in `.env` private keys (`process.env.FIREBASE_ADMIN_PRIVATE_KEY!.replace(/\\n/g, "\n")`), resolving a common deployment bug.
- **Onboarding:** Very clear implementation.

### `apps/buddy-live/src/lib/paths.ts`
- **Clarity:** Excellent utility that consolidates all path formatting logic for Firestore collections and Storage paths.
- **Redundancy/Legacy:** None. By centralizing these path strings, it prevents drift across API routes and client hooks.
- **Onboarding:** Immediate onboarding helper for database mapping.

### `services/buddy-live-adk/app/main.py`
- **Clarity:** Entrypoint exposing `/health` and `/chat/completions`. Maps ElevenLabs Custom LLM requests to ADK execution runs.

## Recommendations & Suggestions

Based on our three core pillars, we have compiled the following prioritized optimizations:

### 1. Clarity Improvements

#### High Priority: Unified Schema and Database Case-Normalization
- **Files Affected:** `apps/buddy-live/src/lib/types.ts`, `services/buddy-live-adk/app/models.py`, `services/buddy-live-adk/app/tools/rep_capture.py`
- **Context:** Currently, client types and database documents have duplicated parameters to account for case mismatches (e.g. `storage_path` vs `storagePath`, `job_id` vs `jobId`, `peek_url` vs `peekUrl`).
- **Recommendation:** Standardize on a single naming convention (such as `snake_case` for all database properties) and remove camelCase fallbacks from TypeScript types.
- **Severity:** Medium · **Effort:** Small

#### Medium Priority: Auto-Generate TypeScript Definitions from FastAPI Schemas
- **Files Affected:** `apps/buddy-live/src/lib/types.ts`
- **Context:** The FastAPI endpoint `/chat/completions` consumes specific JSON payloads described by Pydantic schemas, but these are manually typed in the Next.js client.
- **Recommendation:** Integrate `openapi-typescript` in the frontend workflow to automatically pull and generate schemas from the backend, eliminating manual schema drift.
- **Severity:** Low · **Effort:** Small

---

### 2. Redundancy & Legacy Code Removal

#### Medium Priority: Clean Up Duplicate Storage and Rules Assets
- **Files Affected:** `infra/firestore.rules`, `infra/storage.rules` (compared against `firestore.rules.merged` and `storage.rules.merged`)
- **Context:** Having separate base rules alongside `.rules.merged` variants creates confusion on which rules are actually deployed or modified during local testing.
- **Recommendation:** Consolidate these files. Use standard variable-based rules files and add a quick deploy/sync task in the infra configuration.
- **Severity:** Low · **Effort:** Small

---

### 3. Developer Onboarding Enhancements

#### High Priority: Root-Level Dev Orchestrator (Single Command Start)
- **Files Affected:** Root workspace (New root `Makefile` or `docker-compose.yml`)
- **Context:** Starting the application locally requires a developer to spin up multiple separate terminals, install packages under different systems, run Next.js, run FastAPI, and configure an `ngrok` tunnel separately.
- **Recommendation:** Create a root-level task runner (e.g., a root `Makefile` utilizing `concurrently` or a `docker-compose.yml` environment) to orchestrate starting the web app, backend, and ngrok tunnel simultaneously.
- **Severity:** High · **Effort:** Medium

#### Medium Priority: Central Setup Script for Environment Variables
- **Files Affected:** Root `.env.example`, `apps/buddy-live/.env.local`, `services/buddy-live-adk/.env`
- **Context:** Environment variables are currently spread across three different configurations, creating setup friction for new contributors.
- **Recommendation:** Introduce a root setup script (e.g., `bin/setup.sh`) that reads the central `.env.example` file and copies, maps, and validates the variables into the respective service-level `.env` configs automatically.
- **Severity:** Medium · **Effort:** Small
